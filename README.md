# local-llm-doctor

**你的本地 LLM 跑得很慢，但沒有任何錯誤訊息——這支工具告訴你為什麼。**

給裝了 Ollama、能跑起來、但不懂底層在幹嘛的人。你不需要知道 VRAM 和 RAM 差在哪，
也不需要看懂 `torch 2.5.1+cpu` 是什麼意思。

雙擊 `run.bat`，十秒後你會拿到一份用人話寫的報告，告訴你問題在哪、以及一行可以直接
複製貼上的解法。

## 怎麼用

**需要：** Windows + WSL2 + NVIDIA 顯示卡 + Ollama。

**下載：** 在這個頁面點綠色的 `Code` 按鈕 → `Download ZIP`，解壓縮到任何資料夾。
或者用指令：

```bash
git clone https://github.com/Carinoasd/local-llm-doctor.git
```

**執行：** 雙擊資料夾裡的 `run.bat`。

就這樣。它會自動呼叫 WSL 跑完檢查，然後用瀏覽器打開報告。

> 想在 WSL 終端機裡直接跑也可以：`./check.sh`

### 兩個入口，差別在這裡

| 檔案 | 做什麼 | 什麼時候用 |
| --- | --- | --- |
| `run.bat` | 只讀取現況，不動你的電腦 | 平常、或你**正在覺得慢**的當下 |
| `run-live.bat` | 自動載入一個小模型實際跑一次，再檢查 | 模型已經閒置、但你想知道完整狀況時 |

**為什麼需要第二個。** 這個工具最有價值的幾項檢查——模型有沒有塞進顯示卡、對話長度
會不會爆掉、誰在跟你搶顯存——**全部只有在模型正在記憶體裡的時候才查得到**。
而 Ollama 預設閒置五分鐘就會把模型卸載。

實際發生的狀況是：使用者覺得慢 → 去找這個工具 → 跑起來，中間往往超過五分鐘，
結果最重要的三項全部顯示「略過」。`run-live.bat` 就是為了解決這件事：
它自己載入一個小模型跑一句話，讓那些檢查有真實資料可以判定。

> ⚠️ `run-live.bat` 是這個工具**唯一會改變你電腦狀態**的功能：它會佔用顯示卡記憶體，
> 幾分鐘後由 Ollama 自動釋放。雙擊之後會先問你一次才開始，不想跑可以直接關掉。
> 在終端機裡的等效指令是 `./check.sh --live`。

它還會告訴你速度快不快：

```
實際跑了一次，速度是每秒 334.5 個 token。
（token 是模型輸出的基本單位，數字越大越快。）本專案在同一款顯示卡、同一個模型上
實測到 246.802 tok/s（單次測量），你的是 334.5 tok/s。兩者在同一個量級，看起來正常。
```

**沒有基準就不會亂講。** 速度評價只在「顯示卡」與「模型」都跟
[MEASUREMENTS.md](MEASUREMENTS.md) 裡的基準吻合時才給——換一張沒量過的卡、
或換一個沒量過的模型，它只會報數字，不會假裝知道那算快還是慢。

## 它會告訴你什麼

報告最上面是三行結論，先講重點再講細節。實際遇到問題時長這樣：

```
══════════════════════════════════════════════════════
  檢查完畢，發現 2 個需要處理的問題。最重要的是：模型放不進顯示卡。
  模型有大約 22% 放不進顯示卡，被擠到主記憶體用 CPU 跑。
  先做這件事：先關掉佔用顯示卡記憶體的程式，不夠再換小一號的模型。
  完整步驟在下面「模型放不進顯示卡」那一段。
══════════════════════════════════════════════════════
```

往下每一項都用同一個結構寫：**症狀**（你會感覺到什麼）、**後果**（會怎樣，附實測數字）、
**怎麼修**（可以直接複製的指令或明確的點擊步驟）。技術數值收在「詳細資料」摺疊區，
不會擋在你和答案中間。

其中最有價值的是它會把因果串起來，而不是丟兩個獨立的警告給你自己拼：

> 你的模型需要 16.8 GB，這張卡有 15.9 GB，但現在有 1.9 GB 被其他程式佔著，
> 所以差 2.8 GB 塞不下。這就是上面「模型放不進顯示卡」的原因。
> 目前佔用最多、而且可以關掉的是「NVIDIA App 的遊戲overlay」——關掉它很可能就解決了。

### 檢查哪些項目

| | 抓得出什麼問題 |
| --- | --- |
| **模型放不進顯示卡** | 模型有多少比例被擠到 CPU 上跑，以及那會慢多少 |
| **完全跑在 CPU 上** | 顯示卡根本沒被用到 |
| **對話長度設太大** | 對話記憶吃掉顯示卡容量；也包含「還放得下但已經變慢」的情況 |
| **WSL 顯示卡驅動** | 在 WSL 裡誤裝了 Linux 版驅動（最常見的踩雷） |
| **其他程式佔用顯存** | 誰在跟你的模型搶顯示卡記憶體，以及哪些可以關、哪些不能碰 |
| **服務沒起來 / 門牌被佔** | Ollama 沒在跑，或 11434 被別的程式佔走 |
| **安裝中途失敗** | 官方安裝指令在缺 `zstd` 的系統上會靜默失敗 |

如果是用 `run-live.bat` 跑的，報告最上面還會多一張卡片，寫著實測速度與它的意義。

還有一份給 AI 看的：報告裡有「**複製診斷資訊**」按鈕，複製出來的是結構化純文字，
可以直接貼給任何 AI 助手追問細節。

## 數字從哪來

報告裡出現的每一個倍率都是**實際量出來的，不是估計、也不是引用他人數據**：

| 溢位程度 | 實測減速 |
| --- | --- |
| 29% 的層在 CPU | **慢 3.32 倍** |
| 82% 的層在 CPU | **慢 8.71 倍** |
| context 開大但仍放得下 | **慢 16%** |

方法、原始條件、以及「沒有量到的部分」都寫在 **[MEASUREMENTS.md](MEASUREMENTS.md)**。

做這件事的起因是：開始之前有兩個互相矛盾的估計（一個說「三成在 CPU 大約慢 20–40%」，
一個推算說「約 2 倍」），差距大到不能兩個都寫進文案，所以決定實際去量。
結果是前者嚴重低估——三成的層被擠到 CPU 就慢 3.3 倍。

規則的完整推導與偵測邏輯在 **[rules-draft.md](rules-draft.md)**。

## 隱私

這支工具的報告設計用途是「複製起來貼給 AI 追問」，所以輸出經過去識別化設計：

- **不會寫出你的帳號名稱。** 所有進入報告的系統路徑都會遮罩成 `/home/使用者/...`
- **會提醒你程式清單的存在。** 顯示卡記憶體的佔用排名含你桌面上的程式名稱，
  報告裡有一行明確警語，請你貼給他人前自行確認
- **預設只讀不改。** `run.bat` / `check.sh` 全程不修改任何系統設定、不需要 sudo、
  不安裝任何東西，唯一的寫入是產出 `report.html`。
  唯一的例外是 `run-live.bat` / `--live`，它會載入一個模型（佔用顯示卡記憶體，
  幾分鐘後自動釋放）——那是它的功能本身，而且雙擊時會先問過你
- **不上傳任何東西。** 沒有網路請求，沒有遙測。純規則判斷，不呼叫任何 LLM——
  因為最需要診斷的時候，你的本地模型正好是壞的或超慢的

## 已知限制

- **只支援 NVIDIA 顯示卡。** 偵測不到就顯示「未偵測到支援的顯示卡」並跳過相關檢查，
  不會報錯。AMD / Intel 不在支援範圍
- **只支援 Ollama。** LM Studio 等其他引擎目前不支援
- **需要 WSL2。** 這是為 Windows + WSL2 環境設計的
- **實測環境是一張 16 GB 級的顯示卡。** 這影響兩件事：
  對話長度的溢位臨界點在別的卡上會不同（報告裡提到的 98304 不是通用值）；
  嚴重程度的分級門檻是依兩個實測點內插的設計判斷，不是量出來的
- **減速倍率只在一台機器上驗證過**，沒有第二台佐證
- **「完全跑在 CPU」等故障情境尚未實測**，那些分支的判定邏輯還沒有在真實故障下驗證過
- **速度基準目前只有兩筆**（同一張卡上的 `llama3.1:8b` 與 `llama3.2:1b`），
  而且各自都是單次測量。所以 `--live` 的評價只回答「是不是同一個量級」，
  不會告訴你「你在正常範圍內」——要講範圍需要多台機器的分佈，我們沒有

## 它不做什麼

**不會自動幫你修。** 它只告訴你該做什麼，由你決定要不要做——動壞別人的環境風險太高。
報告裡的每一條修法都是給你複製貼上的，不是它偷偷幫你執行的。

唯一會動到系統的是 `--live` 載入模型那一步，而那是為了取得診斷資料，
不是在「修」什麼；它也不會下載模型（那動輒好幾 GB，該由你決定）。
